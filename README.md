**There are two activity graphs on this page, and they disagree. That is the point.**

The one further down is GitHub's. It can only count work that happens in GitHub
repositories. Most of mine happens in company repositories on GitLab and
Bitbucket, which GitHub cannot see and never will — no setting changes that.

The card above is the same period, measured differently: a scanner walks every
git repository on my machine and counts the commits I wrote, wherever they live.
It publishes counts only — no repository names, no commit messages, no code — and
it runs itself every night. Since most of that work is in private repositories it
cannot be verified from the outside, so treat it as self-reported with an
auditable method and a public daily trail. The scanner is open source: read it,
or run it on your own machine.

**What I'm building**

**[dev-activity](https://github.com/muratozturk4u/dev-activity)** — the scanner behind the card above  
Walks every git repository on this machine, counts only the commits written by me, publishes numbers. No repository names, no commit messages, no code. Runs itself every night.  
`Python`

**[dev-radar](https://github.com/muratozturk4u/dev-radar)** — a filter for the developer feed  
Pulls the day's raw stream from six open APIs, reads the actual README / article / model card of each candidate, and writes a handful of explained cards. Everything it drops is recorded with a reason — the filter has to be auditable, not trusted.  
`Node` `Claude Code`

**Working with** TypeScript · React · Python · Node · agentic systems · RAG · vector databases · Docker
